## 发现与修正

| 问题 | 修正及验证 |
|---|---|
| npm 镜像访问失败 | 使用 npm 官方 registry，安装和构建通过 |
| 共享 Go 缓存的 uuid 文件损坏 | 使用独立 GOMODCACHE；完整 Go 测试与 WASM 构建通过 |
| 刚安装插件时控制面未下发 | 等待传播后执行 HTTP 验收 |
| 模拟模型未处理 chunked 请求 | 增加 chunked 解码；真实 JSON/SSE 请求通过 |
| Node fetch 未正确设置网关 Host | BFF 使用 http.request，实际路由通过 |
| 管理接口可能暴露内部动作或接受非法字段 | 固定动作/方法白名单、类型和范围校验；网关负例验证余额不变、工单未被占用 |
| Redis Lua 出错不会自动回滚 | 写入前完成校验与序列化，补充畸形参数回归 |
| 空模型列表被编码为对象 | 统一空列表语义，浏览器保存/再次保存/恢复模板通过 |
| BFF 传入 operator 与网关严格校验冲突 | 丢弃客户端 operator，由认证 consumer 产生审计身份 |
| 安装脚本依赖私有 plugin-config.json | 新增公开 scripts/quota-config.json；干净目录测试通过；重新安装显示 unchanged |
| 插件 YAML 示例优先级不一致 | 统一为 750，与实际验证链一致 |

失败阶段日志保留为 `server-tests-red.log` 和 `plugin-boundary-red.log`，最终通过结果以上表为准。一次 query-key 负例误用有效应用 Key，已立即轮换，最终负例使用无效占位值；公开证据不含凭据。
