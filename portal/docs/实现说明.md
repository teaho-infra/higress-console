# 实现说明

## 需求对照

| 飞书需求 | 首版实现 |
|---|---|
| 三档额度 | L1/L2/L3 模板、模型列表、64 位以上范围数值校验 |
| 个人优先/部门兜底 | 用户与认证应用比较档位，较高者扣账，等档个人优先 |
| 双维度统计 | 每次响应同时增加两个主体 usage/requests，仅 payer 增加 spent |
| 双周周期与重置 | 14 天周期隔离账本，基准持久、临时档位/加量不结转，刷新不回赠 |
| 多次加量与查询 | delta、query、usage、accounts；工单幂等 |
| 403/429 可区分 | 定制额度插件403，原生窗口插件429 |
| 配置与可视化 | 独立 Portal 四个页面、配置抽屉、真实余额与审计 |
| 审批链路 | 提供认证、幂等、周期校验回调接口；外部 cn-onestop 未接通 |
| 自动分档/低使用降档 | 暂不实现，基准档位由管理员配置 |

## 与文档示意的差异

1. 文档把每周期 ID 混用 `W47` 和 `W47-A/B`；实现统一起始日 `YYYY-MM-DD`，14 天一个周期、结束边界排他。
2. 单独 SETNX 再刷新余额并不原子，也不能靠永久周期标记完成下一次重置。实现按周期保存完整账本，Lua 在一次执行内检查、初始化、扣减或记录变更。
3. Redis Lua 不自动回滚已完成写入。所有入参、结果数值、快照与审计序列化先完成，再提交变更。
4. 请求阶段优先级高的插件先执行，响应阶段反向；认证阶段在默认阶段之前。当前独立链为清除伪造 consumer → key-auth → statistics900 → quota750 → ratelimit600。定制额度插件自身解析 usage，不假设日志即实时准入。
5. 档位模板只影响未来初始化，升档使用新模板但保留 spent/addon，避免修改模板时把使用量清零。
6. 单独命名空间账本替代文档中多个可配置键前缀，以方便原子双账户记账；仅固定 user/app 两维度。
7. 未配置 dimensions 时沿用上游单 consumer 模式，并运行复制的上游回归测试；新模式的管理接口返回结构化 JSON。

## 数据和权限

浏览器只持有 HttpOnly 会话 Cookie 和内存 CSRF token。管理 Key 位于本机 .env，BFF 固定转发到 quota 管理路径。用户不能选任意上游 URL。实际审计操作人由网关 Key Auth consumer 决定。

演示命名空间前缀 `wmt_portal_demo:`；不读取旧 `walmart-jwt-demo:quota:` 余额。业务身份头只接受可信调用方的声明，本轮没有构建企业身份目录同步。生产交付前需补充身份绑定、持久化、部署发布与外部审批验收。

补充复现文件：`scripts/quota-config.json` 保存不含凭据的默认三档配置；`tests/deploy_config_test.py` 验证无既有私有文件时可生成安装清单。
