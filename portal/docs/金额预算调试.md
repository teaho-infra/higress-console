# 金额预算实现与调试

本轮需求：个人档位优先；未配置时继承部门模板；每人独立额度；模型按输入/输出 Token 单价扣人民币预算。部门关系由 Portal 管理维护。所有验收只调用本地模拟模型。

| 文件 | 用途 |

## API 示例

以下是由 Portal BFF 提交的请求体示例；网关仅允许经过 key-auth 的 quota-admin。每次先读取 meta 获取当前 period，ticket_id 使用新的实际工单号。

部门 L3 模板：

```json
{"dimension":"department","subject":"研发部","tier":"L3","period":"从meta读取","ticket_id":"DEPT-001"}
```

个人 L1 优先（POST assign）：

```json
{"dimension":"user","subject":"alice","department":"研发部","tier":"L1","period":"从meta读取","ticket_id":"USER-001"}
```

个人继承部门、独立余额（POST assign）：

```json
{"dimension":"user","subject":"bob","department":"研发部","tier":"inherit","period":"从meta读取","ticket_id":"USER-002"}
```

模型价格（POST prices，全量替换）：

```json
{"prices":{"demo-model":{"input_price_micros":2000000,"output_price_micros":8000000}},"period":"从meta读取","ticket_id":"PRICE-001"}
```

这里对应输入 ￥2、输出 ￥8 / 百万 Token。输入 10、输出 20 的请求扣 180 微元（￥0.000180），不是 30 元，也不是 30 微元。追加 ￥12.34 使用 POST delta 的 `value:12340000`。

## 调试修正与边界

- 明确个人 L1 优先于部门 L3，去掉比较档位高低后选择付款方的旧规则。
- 金额版强制可信用户标识；无有效个人/部门配置时拒绝。给未配置用户单独加钱也不能绕过配置要求。
- 两项费用使用 Go 大整数相加后统一向上取整；实际 Token、应用汇总和用户金额分开保存。
- 价格在准入时固定；延迟模拟请求证明处理中改价只影响后续请求。
- 账本模式冲突拒绝加载，避免误将 Token 当钱。新前缀避免破坏历史实验。
- 计数或费用溢出会记录阻断状态，后续调用失败关闭，需管理员核查；防止长期反复生成无法入账的免费响应。
- GET 查询不初始化或重置预算。部门改档不重算本周期已初始化个人；改个人配置会保留已消费与加量。

仍采用响应后扣账：并发可能短暂超额；无 usage 的响应无法计算费用；结算网络故障没有持久化重试队列。没有钱包、自定义周期、真实模型价格来源或审批系统接入。模拟环境 Redis 无持久化。

最终测试输出、截图与运行哈希保存到 [evidence-money](evidence-money)。上一版 [evidence](evidence) 是历史 Token 版结果，不能作为本版验收。

部署及边界回归中还修正：应用汇总界面读取 cost_micros（不是用户专属 spent）；价格输入上限与账本精度一致；输入与输出 Token 合计超限也会阻断后续调用；旧 Token 模式拒绝误接金额账本前缀。
